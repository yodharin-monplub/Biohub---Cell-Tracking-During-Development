# Model index

One line per experiment. Each folder's `readme.txt` explains the hypothesis, the method and the verdict;
`score.txt`, when present, holds the recorded result. The project overview is the [repository README](../README.md).

This file is generated by `Other/scripts/build_model_index.py` from the readme titles, the `score.txt` files and
`Other/leaderboard_results.csv`. The leaderboard columns are filled only for the 13 models submitted to Kaggle
(model190 twice). The private leaderboard used about 71% of the test data and decided the final ranking.

**How to read the scores.** "Visible-4" means the 4 example test movies Kaggle ships with the data. "Validator"
means the public notebook's own 8 training movies. "Held-out" means a model trained on one embryo and scored on
the other (the only honest local test; see `Other/VALIDATION_AUDIT.txt`). Scores on training movies are
optimistic, because the public checkpoints were trained on them.

**Phases**

| Models | Phase |
|---|---|
| 1–76 | Start from a public 0.934 pipeline (`model1`); one-knob post-processing probes: detector thresholds, motion costs, gap closing, division repair, edge calibration |
| 77–88 | Fine-tuning pilots on rented GPUs, checkpoint interpolation and "soups", and a leaderboard failure analysis |
| 89–152 | Repairs inside the full `model1` pipeline: link protection, relinking, ILP costs, division recovery and vetoes, many label audits |
| 153–166 | Embryo-disjoint validation: clean fold training, held-out folds, cloud-training infrastructure |
| 167–181 | Switch to the public 0.947 notebook (`model167`, our best); radius, division-guard and relink variants |
| 182–189 | Honest held-out-embryo testbed: synthetic pretraining, extra seeds, longer training |
| 190–203 | Our trained or fine-tuned checkpoints inside the 0.947 pipeline: every one submitted lost on the leaderboard |
| 206–209 | Divisions: public DivNet audit, our own division detector, official-metric comparison, final submission |
